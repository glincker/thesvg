## Por que o theSVG

Logos de marcas ficam espalhados por press kits, arquivos do Figma e repositórios aleatórios do GitHub. O **theSVG** é a fonte única de ícones SVG: logos de marcas, diagramas de arquitetura de nuvem e um conjunto de ícones de interface desenhados por nós. Com busca, versionado e disponível como pacotes npm, CDN, CLI, API e servidor MCP.

Todo dev já correu atrás do logo de uma empresa: um press kit enterrado a três cliques de distância, um PNG que fica borrado em telas retina, um arquivo "mono" que na verdade tem quatro cores, um logo que mudou no mês passado. A maioria dos conjuntos de ícones cobre glifos de UI. Ninguém tratou logos de marcas como dados de verdade, versionados e confiáveis.

O theSVG trata. É um catálogo aberto em que cada logo é **oficial, limpo, completo e atual**, entregue no formato que o seu projeto precisar.

### Por que o criamos

O theSVG nasceu de um pull request. Tentamos adicionar o logo do nosso próprio produto, o [AskVerdict](https://www.askverdict.ai), a uma biblioteca de logos open source já existente, e o pedido foi recusado por estar fora do escopo do projeto, o que é uma decisão justa para um conjunto curado. Isso nos fez querer um catálogo em que qualquer marca real, grande ou pequena, possa entrar com uma revisão simples. Hoje o theSVG reúne mais de 7,900 ícones, vindos de materiais oficiais das marcas e conferidos antes de cada merge.

**UM LUGAR PARA TODA MARCA.**

### O padrão theSVG

O que se exige de cada ícone do catálogo e o que queremos que um SVG de marca signifique em qualquer lugar:

| Princípio | O que significa na prática |
| --- | --- |
| **Oficial, sem alterações** | Tirado do kit ou do site da própria marca, com licença e link para as diretrizes em cada entrada. Sem redesenhos. |
| **Variantes completas** | `default`, `mono`, `light`, `dark` e `wordmark` sob um esquema de nomes previsível, então `{slug}/{variant}.svg` sempre funciona. |
| **Realmente limpo** | Um validador roda no CI a cada arquivo alterado: sem scripts, sem rasters embutidos, sem valores `null` ou `NaN`, arquivos mono são mesmo de uma cor só e o `viewBox` está sempre presente. |
| **Rebrands preservam o histórico** | Quando uma marca troca de logo, o novo símbolo passa a ser o atual e o antigo fica como uma entrada `-legacy`, com link nos dois sentidos. Nada some em silêncio. |
| **Legível por máquinas** | Um manifesto estático, `llms.txt`, um servidor MCP e URLs de CDN estáveis, para que ferramentas e assistentes de IA usem os logos com a mesma confiança que as pessoas. |
| **Aberto a todos** | Código MIT, sem contas, sem chaves de API, sem gatekeeping. Se a marca é real, ela tem lugar aqui. |

Se esta é a biblioteca de logos que você sempre quis que existisse, a coisa mais útil que você pode fazer é **[dar uma estrela no repositório](https://github.com/glincker/thesvg)**. É assim que outros devs o encontram.

### Ícones de UI

**Novidade no theSVG 4.0.** Ao lado do catálogo de marcas, o theSVG traz um conjunto de **ícones de interface que nós mesmos desenhamos**, em [thesvg.org/ui](https://thesvg.org/ui). Hoje são 129 ícones, cada um em sete estilos (outline, glass, duotone, offset, fill, glass outline e depth), todos usando `currentColor`, com mais chegando em pequenas levas. Formam uma seção separada, com dados, pacotes e testes próprios, e os dois tipos de ícone nunca misturam dados nem código. Veja [Ícones de UI](#ícones-de-ui-1) mais abaixo.

### Bandeiras

Explore em [thesvg.org/collection/flags](https://thesvg.org/collection/flags). Todos os países da ISO 3166-1 mais Inglaterra, Escócia, País de Gales, Catalunha, País Basco, Galiza, Comunidade Valenciana, Ilhas Baleares, Ilhas Canárias, Córsega, Occitânia, a UE e a ONU, em três formatos. Os slugs seguem o padrão `flag-<code>` (`flag-us`, `flag-gb-eng`); as variantes são `default` (4x3), `square` e `circle`.

```bash
npm i @thesvg/flags
```

```tsx
import { FlagUs } from "@thesvg/flags/react/us";
import { getFlagForLocale } from "@thesvg/flags/locale";

<FlagUs variant="circle" size={32} />
```

Para uma imagem simples não precisa instalar nada: `https://cdn.jsdelivr.net/npm/@thesvg/flags/dist/svg/4x3/us.svg` (use `1x1` ou `circle` para os outros formatos).

No site, cada bandeira tem a própria página (`/icon/flag-us`) com paleta de cores, botões de copiar e baixar, um cartão de como usar (npm, CLI e CDN) e dados rastreáveis por buscadores. ## Variantes

Os ícones aceitam até 7 variantes para qualquer contexto de design:

| Variante | Chave | Descrição |
|---------|-----|-------------|
| Default | `default` | Cor principal da marca |
| Mono | `mono` | Herda a cor do texto |
| Light | `light` | Preenchimento escuro, para fundos claros |
| Dark | `dark` | Preenchimento claro, para fundos escuros |
| Wordmark | `wordmark` | Logo só com texto |
| Wordmark Light | `wordmarkLight` | Logo de texto em branco |
| Wordmark Dark | `wordmarkDark` | Logo de texto escuro |

Nem todo ícone tem todas as variantes. A `default` está sempre presente.

## Ícones de UI

Ícones de interface que nós mesmos desenhamos, em sete estilos. Veja em [thesvg.org/ui](https://thesvg.org/ui).

```bash
npm install @thesvg/ui-react
```

```tsx
import { BellIcon, BellGlassIcon } from "@thesvg/ui-react";

// Outline is the plain name, every other look adds its name.
<BellIcon size={24} aria-label="Notifications" />
<BellGlassIcon size={32} />
```

Um export por estilo significa que um estilo que você não importa nunca entra no seu bundle. Os pacotes de Vue, Svelte e React Native seguem a mesma nomenclatura (`@thesvg/ui-vue`, `@thesvg/ui-svelte`, `@thesvg/ui-react-native`).

| O quê | Onde |
|------|-------|
| Um arquivo de ícone | `https://thesvg.org/ui/{slug}/{look}.svg` |
| Todos os ícones em um estilo | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui/looks/{look}.json` |
| Manifesto (slugs, tags, categorias, qualidade) | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui-icons.json` |
| CLI | `npx @thesvg/cli add ui:bell --look glass` |

Estilos: `outline`, `glass`, `duotone`, `offset`, `fill`, `glass-outline`, `depth`. Os ícones de UI são desenhos originais, lançados sob a [licença MIT](./LICENSE) como o restante do código. Para adicionar ou alterar ícones, veja [Contribuindo com ícones de UI](./CONTRIBUTING.md#ui-icons).

## API

<details>
<summary>Manifesto estático, espelhos e exemplos</summary>

O thesvg é um site totalmente estático, servido por um CDN. Não existe API dinâmica; em vez disso, dois manifestos JSON pré-gerados cobrem todos os casos de uso. Busca, filtros e paginação acontecem no cliente.

URL base: `https://thesvg.org`

| Endpoint | Descrição |
|----------|-------------|
| `GET /api/registry.json` | Manifesto completo dos ícones (slug, título, aliases, categorias, hex, url, chaves de variantes) |
| `GET /api/categories.json` | Lista de categorias com contagens |
| `GET /icons/{slug}/{variant}.svg` | Arquivo SVG bruto (ex.: `/icons/openai/default.svg`) |

```bash
# Fetch the manifest once, filter client-side
curl "https://thesvg.org/api/registry.json" | jq '.icons[] | select(.slug | contains("openai"))'

# Then pull the SVG you want
curl "https://thesvg.org/icons/openai/default.svg"
```

### Mirrors

Para apps com muito tráfego, use o jsDelivr (grátis, baseado no GitHub) em vez de acessar o `thesvg.org` diretamente:

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/icons.json
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/{slug}/{variant}.svg
```

`src/data/icons.json` é o manifesto de referência (os mesmos dados que geram o `/api/registry.json`, com todos os campos de cada ícone, incluindo `license` e `dateAdded`).

Você também pode clonar o repositório (~30 MB) e hospedar por conta própria. O código tem licença MIT; os ícones de cada marca continuam sendo marcas registradas de seus respectivos donos (veja [LEGAL.md](./LEGAL.md)).

> Uma API com token e acesso controlado está no roadmap em `api.thesvg.org`, para recursos avançados (relevância de busca, análise de uso, webhooks). Até lá, o manifesto estático acima é o caminho de integração suportado.

## Rodar localmente

Você precisa do [Node.js](https://nodejs.org) 20 ou mais recente e do [pnpm](https://pnpm.io).

```bash
git clone https://github.com/glincker/thesvg.git
cd thesvg
pnpm install
pnpm dev          # http://localhost:3333
```

| Comando | O que faz |
| --- | --- |
| `pnpm dev` | Inicia o site com hot reload na porta 3333 |
| `pnpm build` | Regenera a API, o `llms.txt`, o feed e os tons dos ícones, e depois gera o site estático |
| `pnpm lint` | Roda o ESLint |
| `pnpm test` | Roda a suíte do Vitest e os testes da CLI e do pacote de ícones |
| `npx tsx scripts/validate-icons.ts` | Audita todos os SVGs em busca de scripts, valores inválidos, arquivos mono que não são mono e `viewBox` ausente |

**Adicionar um ícone:** coloque os arquivos em `public/icons/{slug}/` (`default.svg`, mais `mono`, `light`, `dark` ou `wordmark`, conforme o caso), registre o slug em `src/data/icons.json`, rode o validador e abra um pull request. As regras completas estão no [CONTRIBUTING.md](./CONTRIBUTING.md).
