## theSVG क्यों

ब्रांड लोगो प्रेस किट, Figma फ़ाइलों और बिखरे हुए GitHub रिपॉज़िटरी में फैले पड़े हैं। **theSVG** SVG आइकन का एकमात्र स्रोत है: ब्रांड लोगो, क्लाउड आर्किटेक्चर डायग्राम और हमारे अपने बनाए इंटरफ़ेस आइकन। खोजने योग्य, वर्जन वाले, और npm पैकेज, CDN, CLI, API और MCP सर्वर के रूप में उपलब्ध।

हर डेवलपर ने कभी न कभी किसी कंपनी का लोगो ढूँढा है: तीन क्लिक अंदर दबी प्रेस किट, रेटिना पर धुंधली दिखने वाली PNG, एक "मोनो" फ़ाइल जो असल में चार रंगों की है, या पिछले महीने बदल चुका लोगो। ज़्यादातर आइकन सेट UI ग्लिफ़ तक सीमित हैं। ब्रांड लोगो को भरोसेमंद, वर्जन वाले असली डेटा की तरह किसी ने नहीं सँभाला।

theSVG यही करता है। यह एक खुला कैटलॉग है जहाँ हर लोगो **आधिकारिक, साफ़, पूरा और अद्यतन** है, और आपके प्रोजेक्ट को जिस रूप में चाहिए उसी रूप में मिलता है।

### हमने इसे क्यों बनाया

theSVG की शुरुआत एक पुल रिक्वेस्ट से हुई। हमने अपने ही प्रोडक्ट [AskVerdict](https://www.askverdict.ai) का लोगो एक मौजूदा ओपन सोर्स लोगो लाइब्रेरी में जोड़ने की कोशिश की, और उसे प्रोजेक्ट के दायरे से बाहर बताकर अस्वीकार कर दिया गया। चुने हुए सेट के लिए यह उचित फ़ैसला है। इसी से हमें ऐसा कैटलॉग बनाने का विचार आया जिसमें बड़ा हो या छोटा, कोई भी असली ब्रांड एक सरल समीक्षा से जुड़ सके। आज theSVG में 7,900 से ज़्यादा आइकन हैं, जो आधिकारिक ब्रांड एसेट से लिए गए हैं और हर एक के मर्ज होने से पहले जाँचे जाते हैं।

**हर ब्रांड के लिए एक ठिकाना।**

### theSVG मानक

कैटलॉग का हर आइकन जिन कसौटियों पर खरा उतरता है, और हम चाहते हैं कि ब्रांड SVG का मतलब हर जगह यही हो:

| सिद्धांत | व्यवहार में इसका मतलब |
| --- | --- |
| **आधिकारिक, बिना बदलाव के** | ब्रांड की अपनी किट या साइट से लिया गया, हर एंट्री पर लाइसेंस और दिशानिर्देशों का लिंक। कोई दोबारा बनाई गई ड्रॉइंग नहीं। |
| **पूरे वेरिएंट** | एक अनुमानित नामकरण योजना में `default`, `mono`, `light`, `dark` और `wordmark`, इसलिए `{slug}/{variant}.svg` हमेशा काम करता है। |
| **सचमुच साफ़** | हर बदली हुई फ़ाइल पर CI में एक वैलिडेटर चलता है: कोई स्क्रिप्ट नहीं, कोई एम्बेडेड रैस्टर नहीं, कोई `null` या `NaN` मान नहीं, मोनो फ़ाइलें वाक़ई एक रंग की, और `viewBox` हमेशा मौजूद। |
| **रीब्रांड पर इतिहास सुरक्षित** | जब कोई ब्रांड अपना लोगो बदलता है, नया चिह्न मौजूदा बन जाता है और पुराना `-legacy` एंट्री के रूप में रखा जाता है, दोनों तरफ़ से जुड़ा हुआ। कुछ भी चुपचाप गायब नहीं होता। |
| **मशीन से पढ़ने योग्य** | एक स्टैटिक मैनिफ़ेस्ट, `llms.txt`, एक MCP सर्वर और स्थिर CDN URL, ताकि टूल और AI असिस्टेंट भी लोगो का उतना ही भरोसे से उपयोग कर सकें जितना लोग करते हैं। |
| **सबके लिए खुला** | MIT कोड, कोई अकाउंट नहीं, कोई API कुंजी नहीं, कोई रोक-टोक नहीं। अगर ब्रांड असली है, तो उसकी जगह यहाँ है। |

अगर आप ऐसी ही लोगो लाइब्रेरी चाहते थे, तो सबसे काम की चीज़ जो आप कर सकते हैं वह है **[रिपॉज़िटरी को स्टार करना](https://github.com/glincker/thesvg)**। इसी से दूसरे डेवलपर इसे खोज पाते हैं।

### UI आइकन

**theSVG 4.0 में नया।** ब्रांड कैटलॉग के साथ, theSVG [thesvg.org/ui](https://thesvg.org/ui) पर **हमारे खुद बनाए इंटरफ़ेस आइकन** का एक सेट भी देता है। आज 129 आइकन हैं, हर एक सात रूपों में (outline, glass, duotone, offset, fill, glass outline और depth), सभी `currentColor` का उपयोग करते हैं, और छोटे-छोटे ड्रॉप में और आइकन आते रहेंगे। यह एक अलग सेक्शन है जिसका अपना डेटा, पैकेज और टेस्ट हैं, और दोनों तरह के आइकन का डेटा या कोड कभी आपस में नहीं मिलता। नीचे [UI आइकन](#ui-आइकन-1) देखें।

### झंडे

[thesvg.org/collection/flags](https://thesvg.org/collection/flags) पर देखें। हर ISO 3166-1 देश, साथ में इंग्लैंड, स्कॉटलैंड, वेल्स, कैटालोनिया, बास्क देश, गैलिसिया, वैलेंसिया समुदाय, बैलेरिक द्वीप, कैनरी द्वीप, कोर्सिका, ऑक्सितानिया, EU और UN, तीन आकारों में। स्लग `flag-<code>` होते हैं (`flag-us`, `flag-gb-eng`); वेरिएंट `default` (4x3), `square` और `circle` हैं।

```bash
npm i @thesvg/flags
```

```tsx
import { FlagUs } from "@thesvg/flags/react/us";
import { getFlagForLocale } from "@thesvg/flags/locale";

<FlagUs variant="circle" size={32} />
```

सादी इमेज के लिए इंस्टॉल की ज़रूरत नहीं: `https://cdn.jsdelivr.net/npm/@thesvg/flags/dist/svg/4x3/us.svg` (दूसरे आकारों के लिए `1x1` या `circle` इस्तेमाल करें)।

साइट पर हर झंडे का अपना पेज (`/icon/flag-us`) है, जिसमें उसका रंग पैलेट, कॉपी और डाउनलोड बटन, उपयोग कैसे करें कार्ड (npm, CLI और CDN) और क्रॉल होने योग्य तथ्य हैं। संग्रह पेज क्षेत्र, रंग या लोकेल से फ़िल्टर होता है, और हेडर सर्च झंडों को अलग सेक्शन में दिखाती है ताकि ब्रांड आइकन सबसे ऊपर रहें।

झंडा एक देश है, भाषा नहीं: उसके साथ उस देश की अपनी भाषा का नाम दिखाएँ। गाइड: [docs/flags.md](./docs/flags.md)।

## UI आइकन

हमारे खुद बनाए इंटरफ़ेस आइकन, सात रूपों में। इन्हें [thesvg.org/ui](https://thesvg.org/ui) पर देखें।

```bash
npm install @thesvg/ui-react
```

```tsx
import { BellIcon, BellGlassIcon } from "@thesvg/ui-react";

// Outline is the plain name, every other look adds its name.
<BellIcon size={24} aria-label="Notifications" />
<BellGlassIcon size={32} />
```

हर रूप के लिए एक एक्सपोर्ट का मतलब है कि जो रूप आप इम्पोर्ट नहीं करते वह आपके बंडल में कभी नहीं पहुँचता। Vue, Svelte और React Native पैकेज यही नामकरण अपनाते हैं (`@thesvg/ui-vue`, `@thesvg/ui-svelte`, `@thesvg/ui-react-native`)।

| क्या | कहाँ |
|------|-------|
| एक आइकन फ़ाइल | `https://thesvg.org/ui/{slug}/{look}.svg` |
| एक रूप में सभी आइकन | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui/looks/{look}.json` |
| मैनिफ़ेस्ट (स्लग, टैग, श्रेणियाँ, गुणवत्ता) | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui-icons.json` |
| CLI | `npx @thesvg/cli add ui:bell --look glass` |

रूप: `outline`, `glass`, `duotone`, `offset`, `fill`, `glass-outline`, `depth`। UI आइकन मौलिक ड्रॉइंग हैं जो बाक़ी कोड की तरह [MIT लाइसेंस](./LICENSE) के तहत जारी हैं। आइकन जोड़ने या बदलने के लिए [UI आइकन में योगदान](./CONTRIBUTING.md#ui-icons) देखें।

## API

<details>
<summary>स्टैटिक मैनिफ़ेस्ट, मिरर और उदाहरण</summary>

thesvg पूरी तरह स्टैटिक साइट के रूप में चलता है और CDN से परोसा जाता है। कोई डायनामिक API नहीं है; इसके बजाय दो पहले से बने JSON मैनिफ़ेस्ट हर ज़रूरत पूरी करते हैं। खोज, फ़िल्टर और पेजिनेशन क्लाइंट पर होते हैं।

बेस URL: `https://thesvg.org`

| एंडपॉइंट | विवरण |
|----------|-------------|
| `GET /api/registry.json` | पूरा आइकन मैनिफ़ेस्ट (स्लग, शीर्षक, उपनाम, श्रेणियाँ, hex, url, वेरिएंट कुंजियाँ) |
| `GET /api/categories.json` | गिनती के साथ श्रेणी सूची |
| `GET /icons/{slug}/{variant}.svg` | कच्ची SVG फ़ाइल (जैसे `/icons/openai/default.svg`) |

```bash
# Fetch the manifest once, filter client-side
curl "https://thesvg.org/api/registry.json" | jq '.icons[] | select(.slug | contains("openai"))'

# Then pull the SVG you want
curl "https://thesvg.org/icons/openai/default.svg"
```

### मिरर

ज़्यादा ट्रैफ़िक वाले ऐप के लिए सीधे `thesvg.org` पर जाने के बजाय jsDelivr (मुफ़्त, GitHub पर आधारित) इस्तेमाल करें:

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/icons.json
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/{slug}/{variant}.svg
```

`src/data/icons.json` मूल स्रोत मैनिफ़ेस्ट है (वही डेटा जिससे `/api/registry.json` बनता है, हर आइकन के पूरे फ़ील्ड के साथ, जिनमें `license` और `dateAdded` शामिल हैं)।

आप रिपॉज़िटरी क्लोन (~30 MB) करके खुद भी होस्ट कर सकते हैं। कोडबेस MIT लाइसेंस वाला है; अलग-अलग ब्रांड आइकन अपने-अपने मालिकों के ट्रेडमार्क बने रहते हैं ([LEGAL.md](./LEGAL.md) देखें)।

> `api.thesvg.org` पर उन्नत सुविधाओं (सर्च रेलेवेंस, उपयोग एनालिटिक्स, वेबहुक) के लिए टोकन-आधारित, गेटेड API रोडमैप पर है। तब तक ऊपर का स्टैटिक मैनिफ़ेस्ट ही समर्थित इंटीग्रेशन का रास्ता है।

</details>

## लोकल पर चलाएँ

आपको [Node.js](https://nodejs.org) 20 या नया और [pnpm](https://pnpm.io) चाहिए।

```bash
git clone https://github.com/glincker/thesvg.git
cd thesvg
pnpm install
pnpm dev          # http://localhost:3333
```

| कमांड | यह क्या करता है |
| --- | --- |
| `pnpm dev` | पोर्ट 3333 पर हॉट रीलोड के साथ साइट शुरू करता है |
| `pnpm build` | API, `llms.txt`, फ़ीड और आइकन टोन दोबारा बनाता है, फिर स्टैटिक साइट बिल्ड करता है |
| `pnpm lint` | ESLint चलाता है |
| `pnpm test` | Vitest सूट के साथ CLI और आइकन पैकेज के टेस्ट चलाता है |
| `npx tsx scripts/validate-icons.ts` | हर SVG में स्क्रिप्ट, गलत मान, मोनो न होने वाली मोनो फ़ाइलें और गायब `viewBox` की जाँच करता है |

**आइकन जोड़ें:** फ़ाइलें `public/icons/{slug}/` में रखें (`default.svg`, और लागू हो तो `mono`, `light`, `dark` या `wordmark`), स्लग को `src/data/icons.json` में दर्ज करें, वैलिडेटर चलाएँ, फिर पुल रिक्वेस्ट खोलें। पूरे नियम [CONTRIBUTING.md](./CONTRIBUTING.md) में हैं।
