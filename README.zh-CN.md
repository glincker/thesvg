## 为什么选择 theSVG

品牌 Logo 散落在各家的媒体资料包、Figma 文件和各种零散的 GitHub 仓库里。**theSVG** 是 SVG 图标的统一来源：品牌 Logo、云架构图标，以及我们自己绘制的一套界面图标。可搜索、有版本管理，并提供 npm 包、CDN、CLI、API 和 MCP 服务器。

每个开发者都找过公司 Logo：媒体资料包藏在三层链接之后，PNG 在视网膜屏上发虚，所谓的“单色”文件其实有四种颜色，上个月 Logo 又换了。大多数图标库只覆盖界面符号，没有人把品牌 Logo 当作真正有版本、可信赖的数据来对待。

theSVG 就是这样做的。这是一个开放的目录，每个 Logo 都**官方、干净、完整、最新**，并以你的项目所需的任何形式交付。

### 我们为什么做它

theSVG 始于一个 pull request。我们想把自家产品 [AskVerdict](https://www.askverdict.ai) 的 Logo 添加到一个现有的开源 Logo 库，结果因为超出该项目的范围被拒绝了，对于精选合集来说这很合理。这让我们想做一个目录：任何真实的品牌，无论大小，都能通过简单的审核加入。如今 theSVG 已收录 7,900 多个图标，全部来自官方品牌素材，并在合并前逐一检查。

**每个品牌都有一席之地。**

### theSVG 标准

目录中的每个图标都必须满足以下要求，也是我们希望品牌 SVG 在任何地方都代表的含义：

| 原则 | 实际含义 |
| --- | --- |
| **官方、未修改** | 取自品牌自己的素材包或网站，每个条目都附有许可证和使用规范链接。不重绘。 |
| **变体齐全** | `default`、`mono`、`light`、`dark` 和 `wordmark`，遵循统一且可预测的命名，因此 `{slug}/{variant}.svg` 始终可用。 |
| **真正干净** | CI 会对每个改动的文件运行校验器：无脚本、无内嵌位图、无 `null` 或 `NaN` 值，单色文件确实只有一种颜色，`viewBox` 必须存在。 |
| **品牌换标不丢历史** | 品牌更换 Logo 后，新标成为当前版本，旧标保留为 `-legacy` 条目，二者互相链接。不会悄悄消失。 |
| **机器可读** | 静态清单、`llms.txt`、MCP 服务器和稳定的 CDN 地址，让工具和 AI 助手能像人一样可靠地使用 Logo。 |
| **向所有人开放** | 代码采用 MIT 许可，无需账号，无需 API 密钥，没有门槛。只要品牌真实存在，就属于这里。 |

如果这正是你期待的 Logo 库，你能做的最有用的一件事就是**[给仓库点星](https://github.com/glincker/thesvg)**。其他开发者正是这样发现它的。

### UI 图标

**theSVG 4.0 新增。** 除了品牌目录，theSVG 还提供一套**我们自己绘制的界面图标**，见 [thesvg.org/ui](https://thesvg.org/ui)。目前有 129 个图标，每个都有七种风格（轮廓、玻璃、双色调、偏移、填充、玻璃轮廓和纵深），全部使用 `currentColor`，并会陆续小批量增加。它们是独立的板块，有各自的数据、软件包和测试，两类图标的数据和代码互不混用。详见下文的 [UI 图标](#ui-图标-1)。

- **TypeScript 优先**：完整类型，同时提供 ESM/CJS
- **不限框架**：React、Vue、Svelte、纯 HTML 或 CDN
- **面向 AI**：为 Claude、Cursor 和 Windsurf 提供的 MCP 服务器

### 国旗

在 [thesvg.org/collection/flags](https://thesvg.org/collection/flags) 浏览。涵盖 ISO 3166-1 的每个国家，外加英格兰、苏格兰、威尔士、加泰罗尼亚、巴斯克地区、加利西亚、瓦伦西亚自治区、巴利阿里群岛、加那利群岛、科西嘉、奥克西塔尼亚、欧盟和联合国，提供三种形状。Slug 格式为 `flag-<code>`（`flag-us`、`flag-gb-eng`）；变体有 `default`（4x3）、`square` 和 `circle`。

```bash
npm i @thesvg/flags
```

```tsx
import { FlagUs } from "@thesvg/flags/react/us";
import { getFlagForLocale } from "@thesvg/flags/locale";

<FlagUs variant="circle" size={32} />
```

如果只需要一张普通图片，无需安装：`https://cdn.jsdelivr.net/npm/@thesvg/flags/dist/svg/4x3/us.svg`（其他形状请使用 `1x1` 或 `circle`）。

在网站上，每面旗帜都有独立页面（`/icon/flag-us`），包含配色、复制和下载按钮、使用说明卡片（npm、CLI 和 CDN）以及可被搜索引擎抓取的信息。图标集页面支持按地区、颜色或语言区域筛选，顶部搜索会把旗帜单独分组显示，品牌图标始终排在前面。

旗帜代表的是国家，而不是语言：请在旗帜旁标注该语言的本地名称。指南：[docs/flags.md](./docs/flags.md)。

## 快速开始

```bash
# Add a single icon to your project
npx @thesvg/cli add github

# Or install the package and import only what you use
npm install thesvg
```

```ts
import github from "thesvg/github";

github.svg;      // raw SVG string
github.title;    // "GitHub"
github.hex;      // "181717"
```

```html
<!-- Or use the CDN, no install -->
<img src="https://thesvg.org/icons/github/default.svg" width="32" height="32" alt="GitHub" />
```

每个图标都有独立页面，包含全部变体、复制格式和实时预览，例如 [thesvg.org/icon/github](https://thesvg.org/icon/github)。支持 Tree-shaking，完整类型，ESM 和 CJS。更多内容见 [安装与软件包](./docs/install.md)、[用法与变体](./docs/usage.md) 和 [CDN 与 API](./docs/cdn-api.md)。

## 变体

图标最多支持 7 种变体，适配各种设计场景：

| 变体 | 键 | 说明 |
|---------|-----|-------------|
| 默认 | `default` | 品牌主色 |
| 单色 | `mono` | 继承文字颜色 |
| 浅色 | `light` | 深色填充，用于浅色背景 |
| 深色 | `dark` | 浅色填充，用于深色背景 |
| 文字标志 | `wordmark` | 完整文字 Logo |
| 文字标志（浅色） | `wordmarkLight` | 白色文字 Logo |
| 文字标志（深色） | `wordmarkDark` | 深色文字 Logo |

并非每个图标都有全部变体。`default` 始终存在。

## UI 图标

我们自己绘制的界面图标，共七种风格。在 [thesvg.org/ui](https://thesvg.org/ui) 浏览。

```bash
npm install @thesvg/ui-react
```

```tsx
import { BellIcon, BellGlassIcon } from "@thesvg/ui-react";

// Outline is the plain name, every other look adds its name.
<BellIcon size={24} aria-label="Notifications" />
<BellGlassIcon size={32} />
```

每种风格对应一个导出，所以没导入的风格不会进入你的包。Vue、Svelte 和 React Native 的包沿用相同命名（`@thesvg/ui-vue`、`@thesvg/ui-svelte`、`@thesvg/ui-react-native`）。

| 内容 | 位置 |
|------|-------|
| 单个图标文件 | `https://thesvg.org/ui/{slug}/{look}.svg` |
| 某一风格的全部图标 | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui/looks/{look}.json` |
| 清单（slug、标签、分类、质量） | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui-icons.json` |
| CLI | `npx @thesvg/cli add ui:bell --look glass` |

风格：`outline`、`glass`、`duotone`、`offset`、`fill`、`glass-outline`、`depth`。UI 图标是原创绘制，与其余代码一样以 [MIT 许可](./LICENSE)发布。如需添加或修改图标，请见 [UI 图标贡献指南](./CONTRIBUTING.md#ui-icons)。

## API

<details>
<summary>静态清单、镜像和示例</summary>

thesvg 是一个完全静态的站点，通过 CDN 提供。没有动态 API，而是用两份预先生成的 JSON 清单覆盖所有场景。搜索、筛选和分页都在客户端完成。

基础 URL：`https://thesvg.org`

| 端点 | 说明 |
|----------|-------------|
| `GET /api/registry.json` | 完整图标清单（slug、标题、别名、分类、hex、url、变体键） |
| `GET /api/categories.json` | 带数量的分类列表 |
| `GET /icons/{slug}/{variant}.svg` | 原始 SVG 文件（例如 `/icons/openai/default.svg`） |

```bash
# Fetch the manifest once, filter client-side
curl "https://thesvg.org/api/registry.json" | jq '.icons[] | select(.slug | contains("openai"))'

# Then pull the SVG you want
curl "https://thesvg.org/icons/openai/default.svg"
```

### 镜像

对于高流量应用，请使用 jsDelivr（免费，基于 GitHub），而不是直接请求 `thesvg.org`：

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/icons.json
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/{slug}/{variant}.svg
```

`src/data/icons.json` 是权威清单（与生成 `/api/registry.json` 的数据相同，包含每个图标的完整字段，如 `license` 和 `dateAdded`）。

你也可以克隆仓库（约 30 MB）自行托管。代码库采用 MIT 许可；各个品牌图标仍是其各自所有者的商标（见 [LEGAL.md](./LEGAL.md)）。

> 我们计划在 `api.thesvg.org` 提供需要令牌的 API，用于高级功能（搜索相关性、使用分析、webhook）。在此之前，上面的静态清单是受支持的集成方式。

## 本地运行

你需要 [Node.js](https://nodejs.org) 20 或更高版本，以及 [pnpm](https://pnpm.io)。

```bash
git clone https://github.com/glincker/thesvg.git
cd thesvg
pnpm install
pnpm dev          # http://localhost:3333
```

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 在 3333 端口启动站点，支持热重载 |
| `pnpm build` | 重新生成 API、`llms.txt`、订阅源和图标色调，然后构建静态站点 |
| `pnpm lint` | 运行 ESLint |
| `pnpm test` | 运行 Vitest 测试集，以及 CLI 和图标包的测试 |
| `npx tsx scripts/validate-icons.ts` | 检查每个 SVG 是否含脚本、非法值、非单色的单色文件以及缺失的 `viewBox` |

**添加图标：** 把文件放进 `public/icons/{slug}/`（`default.svg`，以及按需的 `mono`、`light`、`dark` 或 `wordmark`），在 `src/data/icons.json` 中注册 slug，运行校验器，然后提交 pull request。完整规则见 [CONTRIBUTING.md](./CONTRIBUTING.md)。
