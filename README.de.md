## Warum theSVG

Markenlogos sind über Pressekits, Figma-Dateien und zufällige GitHub-Repos verstreut. **theSVG** ist die zentrale Quelle für SVG-Icons: Markenlogos, Cloud-Architekturdiagramme und ein eigenes Set an Interface-Icons. Durchsuchbar, versioniert und verfügbar als npm-Pakete, CDN, CLI, API und MCP-Server.

Jeder Entwickler hat schon einmal nach einem Firmenlogo gesucht: ein Pressekit, drei Klicks tief vergraben, ein PNG, das auf Retina-Displays verschwimmt, eine "Mono"-Datei, die heimlich vier Farben hat, ein Logo, das sich letzten Monat geändert hat. Die meisten Icon-Sets decken UI-Glyphen ab. Niemand hat Markenlogos als echte, versionierte, verlässliche Daten behandelt.

theSVG tut das. Es ist ein offener Katalog, in dem jedes Logo **offiziell, sauber, vollständig und aktuell** ist, und er liefert in der Form aus, die dein Projekt braucht.

### Warum wir es gebaut haben

theSVG begann mit einem Pull Request. Wir wollten das Logo unseres eigenen Produkts, [AskVerdict](https://www.askverdict.ai), in eine bestehende Open-Source-Logobibliothek aufnehmen lassen. Der Antrag wurde abgelehnt, weil er außerhalb des Projektumfangs lag, was bei einem kuratierten Set eine nachvollziehbare Entscheidung ist. Daraus entstand der Wunsch nach einem Katalog, in den jede echte Marke, groß oder klein, nach einer einfachen Prüfung aufgenommen werden kann. theSVG umfasst inzwischen über 7,900 Icons, bezogen aus offiziellen Marken-Assets und vor jeder Aufnahme geprüft.

**EIN ZUHAUSE FÜR JEDE MARKE.**

### Der theSVG-Standard

Woran sich jedes Icon im Katalog messen lassen muss und was ein Marken-SVG überall bedeuten soll:

| Prinzip | Was das in der Praxis heißt |
| --- | --- |
| **Offiziell, unverändert** | Aus dem eigenen Kit oder von der Website der Marke, mit Lizenz und Link zu den Richtlinien bei jedem Eintrag. Keine Nachzeichnungen. |
| **Vollständige Varianten** | `default`, `mono`, `light`, `dark` und `wordmark` unter einem vorhersehbaren Namensschema, sodass `{slug}/{variant}.svg` immer funktioniert. |
| **Wirklich sauber** | Ein Validator läuft in der CI für jede geänderte Datei: keine Skripte, keine eingebetteten Rastergrafiken, keine `null`- oder `NaN`-Werte, Mono-Dateien sind tatsächlich einfarbig, `viewBox` ist immer vorhanden. |
| **Rebrands behalten ihre Geschichte** | Ändert eine Marke ihr Logo, wird das neue Zeichen zum aktuellen und das alte bleibt als `-legacy`-Eintrag erhalten, in beide Richtungen verlinkt. Nichts verschwindet stillschweigend. |
| **Maschinenlesbar** | Ein statisches Manifest, `llms.txt`, ein MCP-Server und stabile CDN-URLs, damit Tools und KI-Assistenten Logos so zuverlässig nutzen können wie Menschen. |
| **Offen für alle** | MIT-Code, keine Konten, keine API-Schlüssel, kein Gatekeeping. Wenn eine Marke echt ist, gehört sie hierher. |

Wenn das die Logobibliothek ist, die du dir immer gewünscht hast, ist das Nützlichste, was du tun kannst, **[dem Repo einen Star zu geben](https://github.com/glincker/thesvg)**. So finden es andere Entwickler.

### UI-Icons

**Neu in theSVG 4.0.** Neben dem Markenkatalog liefert theSVG ein Set von **Interface-Icons, die wir selbst zeichnen**, unter [thesvg.org/ui](https://thesvg.org/ui). Aktuell sind es 129 Icons, jedes in sieben Looks (Outline, Glass, Duotone, Offset, Fill, Glass Outline und Depth), alle mit `currentColor`, und weitere kommen in kleinen Schüben. Sie bilden einen eigenen Bereich mit eigenen Daten, Paketen und Tests, und die beiden Icon-Arten vermischen weder Daten noch Code. Siehe [UI-Icons](#ui-icons-1) weiter unten.

### Flaggen

Zu finden unter [thesvg.org/collection/flags](https://thesvg.org/collection/flags). Jedes Land nach ISO 3166-1 plus England, Schottland, Wales, Katalonien, das Baskenland, Galicien, die Valencianische Gemeinschaft, die Balearen, die Kanaren, Korsika, Okzitanien, die EU und die UN, in drei Formen. Slugs lauten `flag-<code>` (`flag-us`, `flag-gb-eng`); die Varianten sind `default` (4x3), `square` und `circle`.

```bash
npm i @thesvg/flags
```

```tsx
import { FlagUs } from "@thesvg/flags/react/us";
import { getFlagForLocale } from "@thesvg/flags/locale";

<FlagUs variant="circle" size={32} />
```

Für ein einfaches Bild ist keine Installation nötig: `https://cdn.jsdelivr.net/npm/@thesvg/flags/dist/svg/4x3/us.svg` (nutze `1x1` oder `circle` für die anderen Formen).

Auf der Website hat jede Flagge eine eigene Seite (`/icon/flag-us`) mit Farbpalette, Kopier- und Download-Buttons, einer Anleitungskarte (npm, CLI und CDN) und crawlbaren Fakten. Die Sammlungsseite filtert nach Region, Farbe oder Locale, und die Suche im Header zeigt Flaggen in einem eigenen Abschnitt, sodass Marken-Icons zuerst kommen.

Eine Flagge steht für ein Land, nicht für eine Sprache: Zeige den Namen der Muttersprache daneben. Anleitung: [docs/flags.md](./docs/flags.md).

## Varianten

Icons unterstützen bis zu 7 Varianten für jeden Gestaltungskontext:

| Variante | Schlüssel | Beschreibung |
|---------|-----|-------------|
| Default | `default` | Primäre Markenfarbe |
| Mono | `mono` | Übernimmt die Textfarbe |
| Light | `light` | Dunkle Füllung, für helle Hintergründe |
| Dark | `dark` | Helle Füllung, für dunkle Hintergründe |
| Wordmark | `wordmark` | Vollständiges Text-Logo |
| Wordmark Light | `wordmarkLight` | Weißes Text-Logo |
| Wordmark Dark | `wordmarkDark` | Dunkles Text-Logo |

Nicht jedes Icon hat alle Varianten. `default` ist immer vorhanden.

```tsx
import { BellIcon, BellGlassIcon } from "@thesvg/ui-react";

<BellIcon size={24} aria-label="Notifications" />
<BellGlassIcon size={32} />
```

Ein Export pro Look bedeutet, dass ein Look, den du nicht importierst, nie in dein Bundle gelangt. Die Pakete für Vue, Svelte und React Native folgen derselben Namensgebung (`@thesvg/ui-vue`, `@thesvg/ui-svelte`, `@thesvg/ui-react-native`).

| Was | Wo |
|------|-------|
| Eine Icon-Datei | `https://thesvg.org/ui/{slug}/{look}.svg` |
| Jedes Icon in einem Look | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui/looks/{look}.json` |
| Manifest (Slugs, Tags, Kategorien, Qualität) | `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/ui-icons.json` |
| CLI | `npx @thesvg/cli add ui:bell --look glass` |

Looks: `outline`, `glass`, `duotone`, `offset`, `fill`, `glass-outline`, `depth`. Die UI-Icons sind eigene Originalzeichnungen, die wie der restliche Code unter der [MIT-Lizenz](./LICENSE) stehen. Zum Hinzufügen oder Ändern von Icons siehe [Beitrag zu UI-Icons](./CONTRIBUTING.md#ui-icons).

## CDN

Nutze jedes Icon direkt, ohne Installation:

```html
<!-- From thesvg.org -->
<img src="https://thesvg.org/icons/github/default.svg" width="32" height="32" alt="GitHub" />

<!-- From jsDelivr -->
<img src="https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/github/default.svg" width="32" height="32" alt="GitHub" />
```

**URL-Muster:** `https://thesvg.org/icons/{slug}/{variant}.svg`

## API

<details>
<summary>Statisches Manifest, Mirrors und Beispiele</summary>

thesvg wird als rein statische Website über ein CDN ausgeliefert. Es gibt keine dynamische API; stattdessen decken zwei vorgebaute JSON-Manifeste alle Anwendungsfälle ab. Suche, Filter und Paginierung laufen im Client.

Basis-URL: `https://thesvg.org`

| Endpunkt | Beschreibung |
|----------|-------------|
| `GET /api/registry.json` | Vollständiges Icon-Manifest (Slug, Titel, Aliase, Kategorien, Hex, URL, Variantenschlüssel) |
| `GET /api/categories.json` | Kategorieliste mit Anzahlen |
| `GET /icons/{slug}/{variant}.svg` | Rohe SVG-Datei (z. B. `/icons/openai/default.svg`) |

```bash
# Fetch the manifest once, filter client-side
curl "https://thesvg.org/api/registry.json" | jq '.icons[] | select(.slug | contains("openai"))'

# Then pull the SVG you want
curl "https://thesvg.org/icons/openai/default.svg"
```

### Mirrors

Für Apps mit hohem Traffic nutze jsDelivr (kostenlos, GitHub-basiert), statt direkt auf `thesvg.org` zuzugreifen:

```
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/icons.json
https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/{slug}/{variant}.svg
```

`src/data/icons.json` ist das maßgebliche Manifest (dieselben Daten, aus denen `/api/registry.json` gebaut wird, mit allen Feldern pro Icon, einschließlich `license` und `dateAdded`).

Du kannst das Repo auch klonen (~30 MB) und selbst hosten. Der Code steht unter MIT-Lizenz; einzelne Marken-Icons bleiben Marken ihrer jeweiligen Inhaber (siehe [LEGAL.md](./LEGAL.md)).

> Eine geschützte, tokenbasierte API ist unter `api.thesvg.org` für erweiterte Funktionen geplant (Suchrelevanz, Nutzungsanalysen, Webhooks). Bis dahin ist das statische Manifest oben der unterstützte Integrationsweg.

</details>

## Lokal ausführen

Du brauchst [Node.js](https://nodejs.org) 20 oder neuer und [pnpm](https://pnpm.io).

```bash
git clone https://github.com/glincker/thesvg.git
cd thesvg
pnpm install
pnpm dev          # http://localhost:3333
```

| Befehl | Was er tut |
| --- | --- |
| `pnpm dev` | Startet die Website mit Hot Reload auf Port 3333 |
| `pnpm build` | Erzeugt API, `llms.txt`, Feed und Icon-Töne neu und baut dann die statische Website |
| `pnpm lint` | Führt ESLint aus |
| `pnpm test` | Führt die Vitest-Suite sowie die Tests der CLI und des Icon-Pakets aus |
| `npx tsx scripts/validate-icons.ts` | Prüft jedes SVG auf Skripte, ungültige Werte, nicht einfarbige Mono-Dateien und fehlende `viewBox` |

**Icon hinzufügen:** Lege die Dateien in `public/icons/{slug}/` ab (`default.svg`, dazu je nach Bedarf `mono`, `light`, `dark` oder `wordmark`), registriere den Slug in `src/data/icons.json`, führe den Validator aus und öffne dann einen Pull Request. Alle Regeln stehen in [CONTRIBUTING.md](./CONTRIBUTING.md).

**Entwicklungsumgebung einrichten:**

```bash
git clone https://github.com/glincker/thesvg.git
cd thesvg
pnpm install
pnpm dev     # http://localhost:3333
```

**UI-Icons** haben ihren eigenen Ablauf: Bearbeite eine Set-Datei in `src/data/ui/sets`, führe `pnpm ui:build` aus und teste mit `pnpm test:ui`. Marken-Arbeit bleibt bei `pnpm test:brand`. Alle Richtlinien stehen in [CONTRIBUTING.md](./CONTRIBUTING.md).
